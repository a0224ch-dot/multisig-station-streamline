# 精简版升级前检查清单

改功能、打包、上传发布仓、以及站点点「立即更新」之前按序勾选。  
先检索 [踩坑与决策.md](./踩坑与决策.md) 里和本次改动相关的关键词，再看 [CHANGELOG.md](../CHANGELOG.md) 最近几条。

线上更新是否成功，另用 [OTA回归清单.md](./OTA回归清单.md)。新装交付用 [验收清单.md](./验收清单.md)。

---

## A. 改功能 / 打包前

| # | 检查项 | 期望 | □ |
|---|--------|------|---|
| A1 | 已查踩坑手册相关条目 | 与本次改动有关的关键词已读，不是凭记忆 | □ |
| A2 | CHANGELOG 有本版条目 | 客户可见行为写在对应版本下；无新坑则写明「无新坑」 | □ |
| A3 | 有新坑或新约定 | 已写入 `deploy/踩坑与决策.md`，并加进文首关键词表 | □ |
| A4 | 使用说明版本 | `frontend/src/help/helpContent.ts` 的 `HELP_DOC_VERSION` = 根目录 `VERSION` | □ |
| A5 | 外发口径 | README / 使用说明 / help / Release notes **不写**内部档位触发条件 | □ |
| A6 | 对外 notes | 发布说明用「修复已知 BUG / 更新功能」，不写功能细项 | □ |
| A7 | 工作区 | `git status` 只含本版文件；无关改动已移开再打包 | □ |
| A8 | Windows 本机打包 | `frontend/node_modules/@esbuild/win32-x64/esbuild.exe` 存在。没有则按踩坑 #4 重装后再 `bash deploy/pack-release.sh` | □ |
| A9 | 版本号 | `YYYYMMDD` 或同日 `-N`；打包脚本会再写入 `VERSION` | □ |

## B. 上传发布仓前

发布仓只能是 `a0224ch-dot/multisig-station-streamline-releases`。

| # | 检查项 | 期望 | □ |
|---|--------|------|---|
| B1 | 账号能写该仓 | 不要用只能读 Release 的账号。`gh` 报 workflow scope、API 却是 404，按无权限处理，见踩坑 #5 | □ |
| B2 | tag 未占用 | 发布仓没有同名 Release。`20260916-1` 曾只在本机打包、未上传 | □ |
| B3 | zip 是这次提交打的 | 文档或代码又改过，就重新打包，不要传旧 zip | □ |
| B4 | 创建 Release | tag = 版本号，附件为 `streamline-版本.zip` | □ |
| B5 | 更新清单 | 把本次 `dist-release/latest.json` 推到发布仓 **main 根目录** | □ |
| B6 | zipUrl | 指向 `a0224ch-dot/.../releases/download/版本/streamline-版本.zip`，不要指向其它仓 | □ |

只完成 B4、没做 B5 时，站点「检查更新」仍看不到新版。

## C. 站点点「立即更新」前

| # | 检查项 | 期望 | □ |
|---|--------|------|---|
| C1 | 认站点 | `curl -s https://域名/api/health` 含 `"edition":"streamline"`。不要升错到总部或分公司 | □ |
| C2 | 记下配置 | `.env` 的 `PORT`、`JWT_SECRET`、`BRANCH_API_KEY`、`UPDATE_RELEASES_URL`、`OPEN_TOKEN_TTL_SECONDS` | □ |
| C3 | 反代端口 | `/api` 指向本站自己的端口，不是总部 `8788` | □ |
| C4 | 清单地址 | `UPDATE_RELEASES_URL` 指向 a0224ch-dot 的 `latest.json`。若仍指向旧仓，本版升级后会自动迁，但升级前确认你要升的就是这一包 | □ |
| C5 | 可回滚环境 | 先在演示站做 [OTA回归清单.md](./OTA回归清单.md) 的 R0，再生产站再点 | □ |
| C6 | 升级后抽查 | `.env` 与库仍在；原密码能登录；health 仍是 streamline；签名页「有效至」约 15 分钟。`.env` 里仍写 300 是正常的，见踩坑 #1 | □ |

## D. 发版记录约定

1. 用户可见版本必须改 `CHANGELOG.md`。  
2. 修过生产坑或定过约定，必须写 `deploy/踩坑与决策.md`，并补关键词。不要写进被 gitignore 的 `docs/`。  
3. 改了客户能看到的说明，同步 `helpContent.ts` 与中英 `locales`，版本号与 `VERSION` 一致。
