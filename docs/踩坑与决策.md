## 1. 地址校验位 → Invalid address provided

**现象**  
开通 prepare 失败，报 `Invalid address provided`；或前端只见含糊错误。OKX 等钱包扫码后更容易暴露到这一步。

**根因**  
旧逻辑只用正则检查「长得像 T 开头地址」，**不验 base58 校验位**。预置地址（低档 2 址）里错一个字符也能保存，直到 TronWeb `toHex` / 组权限交易才炸，且看不出是哪个地址。

**正确做法**  
- 用 `tronWeb.isAddress`（或封装的 `isValidTronAddress`）做校验。  
- 保存预置地址、开通 prepare、组权限计划前都要验。  
- 报错写明具体地址（如「低档预置地址无效（分公司安全：Txxx）」）。

**别再怎么做**  
- 不要只靠 `/^T[1-9A-HJ-NP-Za-km-z]{33}$/` 当最终校验。  
- 不要让「种子里的示例假地址」带着无效校验位进生产库。

## 2. TronWeb is not a constructor

**现象**  
钱包已打开开通页，后端/构建交易时报 `TronWeb is not a constructor`（或同类）。

**根因**  
依赖为 **tronweb 5.x**（CommonJS 默认导出）时，按 6.x 写法 `const { TronWeb } = await import("tronweb")` 会得到 `undefined`。

**正确做法**  
动态解析构造函数：`mod.TronWeb ?? mod.default?.TronWeb ?? mod.default ?? mod`，确认 `typeof ctor === "function"` 再 `new`。总部与分公司两端保持一致。

**别再怎么做**  
- 不要写死「一定是具名导出」或「一定是 default」。  
- 升级 tronweb 大版本时先跑一条最小 `new TronWeb({ fullHost })` 冒烟。

## 3. 宝塔 `.user.ini` 导致 dist 删不掉

**现象**  
前端构建或在线更新覆盖 `frontend/dist` 失败：`Directory not empty` / 删不掉文件；常见于宝塔站点。

**根因**  
宝塔在网站根（常映射到 `frontend/dist`）放 **`.user.ini`**，并可能 `chattr +i`，普通 `rm -rf` 删不掉。

**正确做法**  
更新/构建前：`chattr -i` → 挪走 `.user.ini` → 覆盖 dist → 挪回并视需要 `chattr +i`。  
在线更新逻辑里把 `.user.ini`、`.env`、数据库、`data/uploads` 列为保护路径。

**别再怎么做**  
- 不要假设 Linux 上 `rm -rf frontend/dist` 一定成功。  
- 不要在更新包里覆盖 `.env` / SQLite 库。

## 4. TronLink「外部请求错误」与深链

**现象**  
扫码能唤起 TronLink，但提示「外部请求错误」。

**根因**  
1. 深链格式不对（旧：错误 query；正确形态接近 `tronlinkoutside://pull.activity?param={JSON}`）。  
2. TronLink 对 DApp 域名有白名单；域名未登记时，格式对了也可能失败。

**正确做法**  
- 深链模板集中在 `walletDeepLinks.ts`，按钱包分别维护。  
- 开通页提供「复制链接 → 钱包内置浏览器粘贴打开」兜底。  
- 需要「扫一扫直接进」时，另行申请钱包白名单，不要只靠改二维码内容幻想解决。

**别再怎么做**  
- 不要把普通 `https://.../o/token` 当成 TronLink 专用 scheme。  
- 不要把「外部请求错误」一律当成我们后端挂了。

## 5. 装修预览码不是开通码

**现象**  
在「公网页装修」扫右侧预览二维码，跳到 `example.com` 或非开通页。

**根因**  
预览码用于看版式；后来改为入口链接预览，**仍不是**当场短时开通会话。

**正确做法**  
真实开通用：后台「开通」页码、公网首页码，或落地页点「开始开通」后的 `/o/{token}`。

**别再怎么做**  
- 不要用装修页预览码给客户开通。  
- 文档/口头培训要说清「入口链接长期有效 ≠ 开通会话短期有效」。

## 6. returnUrl 必须白名单

**现象**  
带 `?returnUrl=` 开通被拒；或担心任意跳转被钓鱼利用。

**根因**  
开放任意 `returnUrl` = 开放开放式重定向。

**正确做法**  
- 后台「对接」配置主机名白名单（支持 `*.example.com`）。  
- **未配置白名单时拒绝任何 returnUrl**。  
- 回跳由服务端校验过的地址生成；参数含 `status` / `address` / `txId` / `ref` 等。

**别再怎么做**  
- 不要在前端信任用户输入的 returnUrl 直接 `location.href` 而不经白名单。  
- 不要为了省事默认放行所有域名。

## 7. 落地页与开通会话分层

**现象**  
想把「装修后生成的链接」当交易所长期模块；若把短时 `/o/token` 当模块链接，很快过期。

**根因**  
开通会话 TTL 短（默认约数分钟）；交易所 H5 需要稳定入口。

**正确做法**  
- 长期入口：`/p/{slug}`（装修页可复制）。  
- 短时开通：用户点「开始开通」或 Partner API 创建后再进 `/o/{token}`。  
- 网络以后台「当前网络」为准，路径不要写死 `/shasta/...` 与后台打架。

**别再怎么做**  
- 不要给交易所发会过期的 `/o/{token}` 当永久入口。  
- 不要第一版就做「每次点生成新的永久随机串」而不做固定 slug。

## 8. 在线更新保护配置与库

**现象**  
担心更新把分公司 `.env`、SQLite、已上传装修图弄丢。

**根因**  
若更新包暴力覆盖安装目录，本地配置与数据会没。

**正确做法**  
- 更新流程：备份 → 覆盖代码/前端 → 装依赖 → migrate → 健康检查；失败自动回滚。  
- 明确保护：`.env`、数据库文件、`data/uploads`、`.user.ini` 等。  
- 发布形态：GitHub Release 附件 zip + 仓内 `latest.json`（含 sha256）。

**别再怎么做**  
- 不要让更新脚本 `git clean` 掉数据目录。  
- 不要只发源码让分公司手拷而跳过校验与回滚。

## 9. 场景只对接入口 URL，不写死钱包深链

**现象**  
想把「需要多签的应用场景」开源传播，并用分公司二维码对接；若场景里写死 TronLink scheme，各钱包/白名单一变全挂。

**根因**  
深链与钱包厂商绑定；分公司入口（`/p/{slug}`）才是稳定对接面。

**正确做法**  
- 场景模板只配置 `entryUrl`（落地页 HTTPS）。  
- 扫码/按钮打开入口；深链由多签站开通页处理。  
- 开源模板见 `examples/multisig-scene-starter`；目录与对接说明见后台「场景」页与 `docs/场景对接说明.md`。  
- 收费做在分公司开通权限侧，不要做进开源包防篡改。

**别再怎么做**  
- 不要给场景发会过期的 `/o/{token}` 当永久模块链。  
- 不要在每个开源场景里复制一套钱包深链表。

## 10. 会员低档 2 址必须绑定专属入口

**现象**  
想给每个会员各自配置低档 2 址，但公网仍只有一个 `/p/exchange` 入口时，开通时不知道该用谁的地址。

**根因**  
低档预置从「全站一套」变成「按账号多套」后，开通会话必须携带归属（`presetOwnerId`），否则只能误用默认址或错用他人址。

**正确做法**  
- 会员专属入口：`/p/u/{会员码}`（系统短码，不可猜）。  
- 从该入口创建的开通会话绑定该会员；prepare 时只取该会员的 LOW 预置。  
- 未配齐 2 址则拒开，禁止静默回退到别人的地址。  
- 管理员只维护 `ownerUserId=branch` 的默认 2 址；不能改会员的 2 址。  
- 会员之间场景与预置互不可见。

**别再怎么做**  
- 不要只在账号里存一份 2 址、却仍让所有人扫同一个无归属二维码。  
- 不要用可猜的用户名当唯一入口码。
